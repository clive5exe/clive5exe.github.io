WOLF: watches obsessively, lacks feelings

The idea

Nobody at retail scale reads 1,896 insider filings a day. Nobody reads every 10-K, cross-references the restatements, and checks them against price action. That information is public, free, and almost entirely unprocessed by individual investors. Institutions solve it by hiring people. A model collapses the cost of reading to nearly zero, and that gap is the only thing here worth chasing.

WOLF trades for you, and the point is to make money. The edge is processing, not prediction. I am not betting a model can forecast markets, because nobody can. I am betting it can read more of what is already public than any other retail participant bothers to, and that acting on that consistently beats acting on a headline and a hunch.

So the model makes the decisions. The application exists to hand it the things a model cannot reach on its own: a broker, market data, filings, fundamentals, insider activity, and a memory of everything it has already done. It is not one hardcoded strategy. Momentum, mean-reversion and insider-following are instruments the model reaches for, not a rule set picked in advance and defended forever. And it is not a dashboard, because a dashboard shows you numbers and leaves the work to you.

Letting a language model act on money is normally reckless. Models hallucinate, cannot do arithmetic reliably, and can be argued into things. The rest of this is how you make that survivable.

Three properties that make it safe

The model has no authority. It proposes. Twenty-one deterministic rules dispose, and the risk engine is the sole issuer of an executable order. ValidatedOrder is constructible only through risk.engine.validate(), is idempotent by construction, expires, and broker adapters type-require one and then re-assert verdict.approved again at the boundary. Only the execution/ package may call submit_order, and that is enforced by import-linting rather than by a code review promising to notice.

It cannot express a dangerous instruction. StructuredThesis is the only accepted shape for model output: bull case, bear case, why now, what changed, invalidation conditions, data gaps, confidence, and the ids of the context items it leaned on. There is no field for size, no field for mode, no field for autopilot. There is nothing to jailbreak, because the vocabulary does not contain the dangerous words. Schema failures are retried once and then recorded as a provider error, never best-effort parsed.

Everything is recorded. Append-only SQLite, UPDATE and DELETE blocked by triggers, every event carrying a ULID, an occurred-at and a recorded-at, a correlation id and a causation id. Derived state is rebuildable from the log, and replay producing an identical hash-compared state is a release gate, not an aspiration. A bad decision is diagnosable rather than deniable.

The model is also never told what the numbers are. It receives proportions, never amounts: a holding is 39.9 percent of the portfolio against a 40 percent target, never $39,914 or 140 shares. That is enforced by type rather than by a filter, so it cannot rot the way a filter quietly rots.

The twenty-one rules

Every configured rule runs on every evaluation. No short-circuiting, so a veto never hides the rules behind it, and the verdict always carries all twenty-one results. Rules are side-effect free. Missing data a rule needs is not a shrug, it is a veto: the rule fails closed.

The interesting cases are the tested failures, not the happy path. Quote missing and max_order_value, max_position_pct and stale_quote all fail closed. Sector unknown on a buy and max_sector_pct fails closed. Event log unreadable and the engine raises outright, which makes execution impossible. Two rapid identical proposals and the second is killed by duplicate_order. Bump the policy version between trigger and validation and policy_changed catches it.

Giving the model tools without giving it the keys

A model that cannot look things up is not researching, it is guessing with citations. So it now gets tools. The uncomfortable part is what that means at the credential layer, and it is worth stating plainly: Robinhood’s MCP server issues exactly one scope, called internal, and there is no read-only variant. An authorised token can place orders. Read-only is not something the credential can promise, so the guarantee cannot come from there. It has to come from the allowlist, which makes the allowlist the entire defence rather than a convenience.

Four things follow from taking that seriously.

The provider passes an intersection, never the caller’s list. A request for tools is filtered against the provider’s own allowlist before it becomes a --allowedTools argument. Ask for something outside it and you do not get an error you can catch and route around, you get silence: the tool is simply absent. The gap between what was requested and what was granted is written to the event log by name, so a prompt reaching for something it was never given is visible afterwards rather than inferred.

The working directory is the boundary. MCP registration is project-scoped, so which directory the CLI runs in decides which servers it can even see. The subprocess is given a tool directory only when tools are actually granted, which means a toolless synthesis cannot inherit an MCP connection it was never meant to reach. That scoping is treated as the safety mechanism rather than an inconvenience to engineer around.

Grants are part of the decision record. The tool names a decision had access to are recorded in the query event alongside the prompt hash. A verdict cannot be judged months later without knowing what the model could see when it formed the thesis, so that list is stored with the same permanence as the thesis itself.

Trade tools cannot be listed at all. Tools carry a class, and broker_trade tools fail config validation while the policy mode is read-only or paper, then get re-checked at call time anyway. The Robinhood adapter’s submit_order raises BrokerCapabilityError in v0.1 regardless of configuration. Requesting an unlisted tool raises ToolPermissionError and is recorded, because that is either a bug or an attack and both are worth keeping.

Underneath, every tool call and response becomes a tool.call and tool.result event with redaction applied, servers are spawned as subprocesses with a clean environment so nothing ambient leaks in, and credentials are injected per server by name from the OS keystore rather than inherited. The tool list is re-probed at startup and any drift is diffed and surfaced, because a server quietly gaining a tool is exactly the change you would otherwise never notice.

Secrets live only in macOS Keychain or libsecret on Linux, and there is deliberately no file fallback. If no keystore is available WOLF refuses rather than writing credentials to disk, because a silent downgrade leaves a machine unprotected with nothing on screen to say so.

Numbers the model never has to compute

Ask a language model for a Sharpe ratio and it returns a plausible wrong number. Ask it to size a position and it is confidently off. So it computes nothing. A separate quant layer produces exact values from bars and the model reads them as facts, which frees it to do the thing it is actually good at, which is weighing evidence and arguing about it.

It is built on numpy, pandas, scipy, statsmodels and arch. Boring, BSD-licensed, and what people who crunch these numbers for a living actually use, all shipping prebuilt wheels so the no-sudo installer never has to compile anything. Momentum, volatility, drawdown, Sharpe, Sortino, correlation and ATR sizing come out of it.

Three details in there are the whole philosophy in miniature. Everything is deterministic and pure, same bars in and same numbers out, no clock reads and no I/O, which is what lets a decision replay byte for byte months later. Floats are used internally because that is what numpy speaks and a Sharpe ratio is an estimate over noisy data where the fifteenth decimal place is meaningless, so money stays Decimal everywhere else and the conversion happens at one deliberate boundary. And the trading year is a named constant of 252 sessions, stated explicitly so a reported Sharpe cannot silently change because somebody assumed 250.

Short windows raise InsufficientHistory rather than returning a number. A momentum score over eleven days is not a small error, it is a different quantity, and a NaN would sort silently to one end of a ranking where nobody would ever see it.

One decision, end to end

Trigger, observe, retrieve, compute candidates, optional AI synthesis, deterministic sizing, risk verdict, mode gate, events and notification. Every event in a cycle carries the same correlation id. A cycle that stops early on stale data or a veto is a successful cycle with outcome no_action and a recorded reason, which is why the journal gives vetoes the same weight as fills.

The layering is enforced mechanically. The core is headless, the interfaces hold zero business logic, and the forbidden import edges are checked by a script: the TUI and CLI may not reach brokers, providers or risk directly, providers may not import brokers, strategies may not import brokers, and nothing at all may import the TUI. It is one of the few architecture rules I have seen survive contact with a real codebase, and it only survives because a machine checks it.

Unattended operation already works. wolf watch runs the whole cycle on a timer with nobody present, and that needs no mode change, because what the ladder gates is real money rather than the absence of a human.

Data, and knowing exactly how old it is

The failure I care about most is not a bad trade. It is a confident trade made on a price from forty minutes ago. So nothing enters a decision without a source, an event time, an ingestion time, a TTL and a credibility score, and no source ships without a license assessment written down first. “Legally questionable” means excluded, not risk-accepted.

Single-venue sentiment can never satisfy the source-diversity floor on its own, so Bluesky aggregates are stamped below_floor until something corroborates them. EDGAR data is point-in-time, so a restatement is visible rather than silently applied backwards over history you already made decisions on, and retrieval re-verifies that nothing newer exists before a decision cites a filing as current. Live sources pulse on screen and stale ones go still, so you notice the absence of motion.

Model output and ingested market text are both treated as hostile input. Schema validation, citation integrity checks, and past all of it the deterministic risk boundary sitting between any text and any order.

The safety ladder

Versions gate on maturity criteria, not dates. Mode 2 needs at least four weeks of dogfooded paper history and zero unexplained replay divergences before it is even a candidate. The kill switch is checked at the scheduler, the cycle, the engine and the execution layer, engaging it is one command, and disengaging it is deliberately awkward: wolf unkill, or two separate presses in the interface.

How you would know it works

Backtesting is not optional, and it is not free, because judgment cannot be replayed for free. Every historical decision is a real model call with a real bill attached. That is a budget constraint, not a reason to skip it. Three things are testable: reconstruct what was knowable on a date and ask the model cold, replay the deterministic half at zero cost, and judge the live record, since every thesis carries an invalidation condition and months of logged decisions eventually say whether it held.

The point-in-time layer already works: stand on 2023-06-01 and the fundamentals return FY2022, never FY2024. This is also why delisted companies have to stay in the universe. Offer a model a 2008 world with Lehman quietly removed and it looks like a genius for not buying it.

What is still missing

The model can look things up now, and it can be trusted with a broker connection because the allowlist does not depend on the credential being polite. What it still cannot do is choose what to look at.

One strategy ships in v0.1, target-allocation rebalancing, and the model argues about the trade that strategy produced. It does not pick the candidates. An engine that reads 1,896 filings a day is worth a great deal less if the thing doing the reading is handed the shortlist. Widening that is the open design question, tracked as T-037, and it is the difference between a system that checks a plan and a system that finds one.

After that: specialised agents with separate tools and prompts for fundamentals, filings and insiders, and technicals, plus an adversary whose only job is to argue the other side before anything reaches risk. Then human-approved execution, which is the first time any of this touches real money. If a piece of work does not make the model a better trader or make its decisions safer to act on, it is not next, and that includes work that is interesting, rigorous and well engineered.

What it does not do

A project that argues for honest software should be honest about itself, so this list is in the README and on the site too.

  • It does not trade real money. v0.1 is read-only intelligence plus paper trading. The paper engine runs the identical proposal, risk and order path live execution will, so the evidence is comparable rather than a toy. It is not investment advice, it does not predict markets, and v0.1 makes no performance claim.
  • Live quotes need a Robinhood Agentic Trading account. Without one, quotes fall back to static demo fixtures and every figure on screen is shaped rather than real.
  • Sharpe, Sortino and beta report “unavailable” until a licensed benchmark series is configured. They are never approximated silently.
  • Paper fills model slippage as a flat bps adjustment. No spread, no partial fills, no market impact, and that is documented in every fill event rather than in a footnote.
  • Max drawdown reflects observed history only. It is computed from recorded equity snapshots, so intraday extremes the runtime never sampled are not in it.
  • The earnings-blackout rule defaults to disabled, because no reliable free earnings-calendar source has been verified yet.
  • The market clock is holiday-naive. It knows regular NYSE hours but not the exchange holiday calendar.

Where it is

v0.1 scaffold. Python, MIT licensed, 589 tests including safety, contract and replay suites, mypy clean, CI on macOS and Linux. The safety suite proves specific things rather than general ones: that no order path bypasses the risk engine, that tampered orders are refused at the broker boundary, that duplicates never re-execute, that the kill switch halts everything, and that hostile context text cannot change a proposal or a verdict.

The name is wealth orchestration, local-first, which is a backronym and I am not going to pretend otherwise. Install is one line, prints what it will do before doing it, touches two paths and needs no sudo. Then wolf setup turns your stated goals into a draft policy you confirm field by field, because a limit you did not read is not a limit you agreed to, and the confirmed struct is the only thing the runtime enforces. The model’s interpretation is a convenience. Alerts go to Notification Center, libnotify, or your own Telegram bot paired in one command.

A patient predator that explains itself. Watches everything, moves only when the numbers say move.
